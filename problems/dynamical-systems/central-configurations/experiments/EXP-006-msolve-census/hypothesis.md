# EXP-006: msolve-engine censuses (completing EXP-002's capped samples; the n = 4 equal-mass planar census)

Declared: 2026-07-24, BEFORE any run. Route: R1/R4 (census instruments). Backlog:
CCB-025 (msolve engine), CCB-009 (certified listing), CC-P1 entry rung.

## Question

Does the msolve engine (Groebner + rational univariate representation + certified
real-root isolation) complete the censuses that saturated our sympy engine, and does
it agree exactly with sympy where both decide? And does the n = 4 equal-mass planar
census reproduce the published class count?

## Setup

msolve 0.10.1 (built in WSL from the algebraic-solving source; binary SHA-256
be6ea2289f0fab9847bf7dec1ef4e89cb66f83da064a7b4b0749876a3d18d8ff), invoked on input
files generated by `cclib` (same enriched systems, cleared over QQ, written in
msolve's polynomial syntax). sympy remains the independent verification layer: every
solution msolve reports is re-checked by exact residual substitution in cclib, and
every count is compared against sympy where sympy decided.

Ground truths available: EXP-002's decided samples (1,1,1) and (1,1,2), each exactly
4 positive points (equilateral + one collinear per ordering); the equal-mass planar
n = 4 count of 4 classes modulo rotation, reflection and permutation
(Moczurad-Zgliczynski 2019), and 50 classes modulo rotation only (Simo 1978, quoted
as a theorem by Albouy 1996 for the equal-mass case).

## Falsifiable predictions

- **P1 (agreement where both decide).** On masses (1,1,1) and (1,1,2), msolve
  returns exactly the same positive real solution sets as EXP-002's sympy census:
  4 points each, matching coordinate by coordinate under exact residual re-check.
- **P2 (completion of the capped samples).** For masses (1,2,3) and (2,3,5), where
  the sympy census exceeded 900 s, msolve completes within a 1800 s cap per sample,
  and the positive real census is again exactly 4 points per sample, one equilateral
  and one collinear per ordering (the Euler-Lagrange-Moulton classification, which
  holds for all positive masses at n = 3).
- **P3 (the n = 4 equal-mass planar census).** On the enriched planar system for
  four equal masses (symmetric + asymmetric AC + Cayley-Menger + energy-inertia),
  msolve's real solution set, reduced modulo the relabeling action and reflection,
  has exactly 4 classes; the square appears with the exact side value of EXP-001
  (minimal polynomial 32x^6 - 32x^3 + 7). Failure of the count is a genuine
  refutation candidate: it would mean either our enriched system is not capturing
  exactly the planar CCs, or the equivalence reduction is wrong.

## Preflight (methodology/12)

- **P1 source-complete.** The ground truths are read from primary sources already in
  our dossiers: MZ19 (PDF read; the appendix report files give the equal-mass class
  counts 2, 4, 5, 9, 14 for n = 3..7) and HM06 (PDF read in full; it states Albouy's
  50 relative equilibria for four equal masses as a theorem, and the 12 collinear +
  6 convex + 14 concave lower-bound decomposition). Nothing further in those papers
  settles the n = 4 equal-mass count differently; no unread source bears on it.
- **P2 tooling smoke test.** Before any capped run, msolve is exercised on a tiny
  instance (the n = 3 equal-mass enriched system, decided in EXP-002 in seconds) to
  confirm it emits parseable output and that our parser round-trips it. Only then do
  the larger samples get machine time.
- **P3 premise dependencies.** (a) The enriched system captures exactly the planar
  CCs once Cayley-Menger is adjoined: supported by EXP-001 (P7 sub-claims) and
  EXP-002 (P3), where the planar rhombus census returned the square alone. (b) The
  n = 3 positive census is exactly 4 points for any positive masses: classical
  (Euler, Lagrange, Moulton), and verified by us on two mass vectors in EXP-002.
  (c) msolve's real-root output is certified: claimed by its authors; we do NOT rely
  on it, since every accepted point is re-verified by exact residual in sympy.
- **P4 one-sidedness.** P1 and P2 are two-sided: agreement confirms both engines on
  those instances, disagreement refutes at least one and stops the lane. P3 is
  two-sided for the COUNT (a wrong count refutes our enriched-system-plus-reduction
  pipeline) but one-sided for correctness of individual solutions: finding the
  square proves the pipeline reaches it, while a missing solution could be either a
  pipeline gap or an equivalence-reduction error, which the artifacts must
  distinguish.
- **P5 invariant-first.** For the equivalence reduction we use the scale-free
  invariant J = U I^(1/2) / M^(5/2) plus the sorted mutual-distance multiset as the
  class key: cheap invariants that separate classes without any geometric
  reconstruction. If they fail to separate two candidate classes, that is reported
  rather than patched.
- **P6 budget and kill criterion.** Per-sample cap 1800 s at n = 3, 3600 s at n = 4;
  total budget 3 hours. If a cell hits its cap, it is recorded inconclusive-cap and
  the lane continues with the decided cells; no cell is retried at a larger budget
  without a new declaration.

## Success / failure criteria

SUCCESS: P1, P2, P3 hold with exact re-verification. FAILURE: any mismatch with the
sympy census where both decide (P1) is a serious instrument alarm and stops the
lane until resolved; a wrong count in P2/P3 is recorded as refuted with the machine
output. Caps report inconclusive-cap honestly.

## Method / environment

`run.py` writes the msolve inputs from cclib, invokes msolve in WSL, parses the
output (rational isolating boxes / RUR), and re-verifies every accepted point in
sympy by exact residual substitution. Deterministic; artifacts tee'd to `artifacts/`
with the msolve version and hashes.
